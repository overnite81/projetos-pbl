Compreendendo os Métodos HTTP (Verbos Web)

No protocolo HTTP, os métodos (ou "verbos") definem a intenção da operação que o cliente deseja realizar sobre um determinado recurso na Web (representado por uma URL). Entender a diferença entre cada um é fundamental para construir APIs RESTful elegantes e eficientes.

GET Consulta

Obter / Listar Recurso

Utilizado para recuperar informações de um servidor sem alterar seu estado. Nunca deve enviar payload no corpo (body).

Seguro (Safe)? Sim (Não altera dados)
Idempotente? Sim
Possui Request Body? Não
Status Tipico: 200 OK / 404 Not Found
POST Criação

Criar Novo Recurso

Envia dados no corpo da requisição para criar um novo registro no servidor. O servidor atribui um novo ID a este objeto.

Seguro (Safe)? Não (Modifica servidor)
Idempotente? Não (Cria múltiplos itens)
Possui Request Body? Sim (JSON/FormData)
Status Tipico: 201 Created
PUT Substituição

Substituição Completa

Substitui **todos os dados** do recurso especificado. Se algum campo for omitido no envio, ele será limpo/reseta do objeto original.

Seguro (Safe)? Não
Idempotente? Sim (Repetir dá o mesmo resultado)
Possui Request Body? Sim
Status Tipico: 200 OK / 204 No Content
PATCH Modificação Parcial

Atualização Parcial

Aplica modificações **parciais** a um recurso existente. Você envia apenas as propriedades que deseja alterar (ex: só o preço).

Seguro (Safe)? Não
Idempotente? Depende da regra
Possui Request Body? Sim
Status Tipico: 200 OK / 204 No Content
DELETE Remoção

Excluir Recurso

Remove o recurso especificado permanentemente do servidor pelo seu identificador (ID).

Seguro (Safe)? Não
Idempotente? Sim
Possui Request Body? Raro/Geralmente Não
Status Tipico: 200 OK / 204 No Content

O que é Idempotência?

Um método é considerado Idempotente se executar a mesma requisição 1 ou 100 vezes seguidas produz exatamente o mesmo efeito colateral no servidor.

• POST não é idempotente (cria um novo item a cada clique).
• PUT é idempotente (substitui o estado com o exato mesmo valor).

Guia Definitivo dos Métodos HTTP & Arquitetura REST

Entenda como funcionam os principais métodos de requisição da Web, suas características de Idempotência e Segurança, e como escolher o método certo para cada situação.

GET
Seguro Idempotente

Leitura de Dados

O método GET é utilizado exclusivamente para solicitar/recuperar dados do servidor. Ele não deve alterar o estado dos recursos no backend.

// Exemplo de endpoint:

GET /api/v1/usuarios?status=ativo

POST
Não Seguro Não Idempotente

Criação de Recursos

O método POST envia dados ao servidor para criar um novo recurso subordinado. Cada execução idêntica gera um novo registro com ID diferente.

// Resposta típica (201 Created):

POST /api/v1/usuarios { "nome": "Maria" }

Qual a diferença real entre PUT e PATCH?

Comparativo Prático
PUT Substituição Completa

Substitui o recurso inteiro. Se você enviar apenas 1 campo, os outros campos omitidos serão limpos ou redefinidos para os valores padrão! 

// Envia o objeto INTEIRO
PUT /usuarios/10
{ "nome": "João", "email": "j@test.com", "idade": 30 }
PATCH Modificação Parcial

Aplica alterações parciais. Modifica apenas os atributos explicitamente declarados no payload, mantendo todos os outros inalterados. 

// Envia APENAS o campo que mudou
PATCH /usuarios/10
{ "email": "novo@email.com" }
DELETE
Não Seguro Idempotente

Remoção de Recursos

Remove o recurso especificado do servidor. Retorna frequentemente status 204 No Content (sem corpo na resposta) ou 200 OK.

Principais Códigos de Status (Status Codes)

200 OK

Requisição bem-sucedida (GET, PUT, PATCH).

201 Created

Recurso criado com sucesso (POST).

204 No Content

Sucesso sem conteúdo no corpo (DELETE).

400 Bad Request

Sintaxe JSON incorreta ou campos inválidos.

401 Unauthorized

Requer autenticação válida (Token/Key).

404 Not Found

O recurso solicitado não existe no servidor.

405 Method Not Allowed

O endpoint não suporta este método HTTP.

500 Internal Error

Falha inesperada ou erro interno do servidor.

Console de Logs HTTP

Nenhuma requisição disparada até o momento.

POST

Criar Nova Tarefa

HTTP Behavior: Envia payload completo via POST /posts. O servidor criará o recurso e retornará status 201 Created com um ID gerado.
PUT

Substituir Objeto Inteiro (PUT)

Atenção PUT: Todos os campos acima serão enviados no payload. O recurso será totalmente substituído pelo novo objeto.
